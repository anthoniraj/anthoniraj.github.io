Time Complexity and Space Complexity

These two ideas help you describe an algorithm in simple terms: how the running time grows and how much extra memory it needs as the input gets bigger.

Time = how much work
Space = how much extra storage
Input size = usually called n

Time Complexity in Simple Terms

If you give the algorithm more data, time complexity tells you how the amount of work changes. It does not mean exact seconds on one laptop. It means the growth pattern. For example, if a search checks one item at a time, doubling the list usually means about twice the work.

Space Complexity in Simple Terms

Space complexity tells you how much extra memory the algorithm needs while it runs. If the algorithm only uses a few variables, its extra space stays small. If it creates a second list as large as the input, memory use grows with the input.

How to Think About It

O(1)

The work stays about the same even if the input grows. Example: reading one element by index from an array.

O(n)

The work grows in a straight line with the input size. Example: scanning every item in a list once.

O(n²)

The work grows much faster because each item is compared with many others. Example: simple nested-loop sorting methods.

Quick memory trick:

Time complexity asks:
"If the input becomes bigger, how much more work do we do?"

Space complexity asks:
"If the input becomes bigger, how much more extra memory do we need?"

Here, n means input size.
